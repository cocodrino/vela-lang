## ADDED Requirements

### Requirement: Dictionary values are espeak-ng phoneme strings
All values in `packages/vela-tts-piper/data/vela-dictionary.json` SHALL be valid espeak-ng phoneme strings (space-separated phonemes, ` . ` for syllable boundaries). Values in dot-syllabified text format (`ha.lo`) are NOT valid and SHALL be replaced.

#### Scenario: Existing entry halo has espeak-ng value
- **WHEN** the dictionary is loaded and `lookupWord("halo", dict)` is called
- **THEN** the returned value SHALL be `h a . l o` (not `ha.lo`)

#### Scenario: Dictionary value for yu uses espeak-ng j not IPA j
- **WHEN** `lookupWord("yu", dict)` is called
- **THEN** the returned value SHALL be `j u` (espeak-ng) which is the correct palatal approximant mapping for VELA `y`

#### Scenario: No dictionary value contains a bare dot without spaces
- **WHEN** all dictionary values are iterated
- **THEN** NO value SHALL match the pattern `/\.\S/` (dot immediately followed by a non-space character)

### Requirement: Dictionary covers all 168 corpus words
The dictionary SHALL contain entries for all unique words found in the 4 corpus texts: `story-lumina-bridge.txt`, `story-song-teacher.txt`, `poem-laif-biutifl.txt`, `poem-pis-hope.txt`.

#### Scenario: All corpus words have a dictionary entry
- **WHEN** the 168 unique corpus words are looked up in the dictionary
- **THEN** each word SHALL return a non-null espeak-ng phoneme string

#### Scenario: G2P-generated entries are phonologically valid
- **WHEN** a corpus word has no hand-tuned entry and is generated by G2P
- **THEN** the generated espeak-ng string SHALL use only the 23 phoneme symbols defined in the canonical phoneme map
